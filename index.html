Product stance

Built for guardian work, not passive demos.

The landing page now matches the current product direction: Seraph is a dense operator surface for memory, intervention, execution, and control.

01

Dense by default

Sessions, approvals, workflows, artifacts, and live trace belong in the same working surface, not behind a decorative shell.

02

Evidence near action

Important claims need provenance, routing context, and visible degraded-state signals close to the decision point.

03

Human override stays explicit

Seraph can act proactively, but approval, interruption, and redirection remain first-class operator controls.

Guardian loop

One system, five reinforcing loops.

Seraph is not just a model wrapper. The product only works when observation, memory, judgment, action, and feedback compound together.

01

Observe

Collect signals from sessions, schedules, screen context, operator commands, and queued work.

02

Model

Maintain a living picture of the human, their goals, current state, and ongoing commitments.

03

Reason

Rank leverage, risk, and timing instead of treating every notification or task as equally useful.

04

Act

Move through tools, workflows, and MCP integrations with policy-aware execution and visible control.

05

Learn

Use intervention results, operator feedback, and long-term memory to improve future decisions.

Shipped foundations

Designed as a real operator surface.

The current repo direction is a power-user guardian workspace with explicit controls, linked evidence, and an extensible execution plane.

In the workspace

What the operator sees

  • Dense multi-pane cockpit with sessions, priorities, approvals, trace, workflows, and artifacts
  • Command-first operation with reusable workflows, saved layouts, and explicit continue or interrupt paths
  • Activity ledger and runtime visibility so operator state does not collapse into a single chat thread
  • Policy-aware controls that keep execution, failure, and degraded mode legible under load

In the system

What keeps it running

  • Persistent identity, long-term memory, and hierarchical goals for longitudinal continuity
  • Proactive scheduling across briefings, reviews, strategist ticks, and maintenance loops
  • Observer and screen-awareness foundations with optional OCR for richer context capture
  • Plug-and-play MCP integration plus local tools, workflows, and open-source runtime control
